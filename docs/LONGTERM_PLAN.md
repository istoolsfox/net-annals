## 二、与 n8n 的分工协议（不冲突机制）

| 环节 | 归属 | 说明 |
|---|---|---|
| 采集/收割（维基年份页、LL2、USGS、新闻门户、热搜） | **n8n**（服务器） | 按本文件第四节源清单配置；产出 gap_queue / daily_queue |

| 核实/写作/验收/入库 | **ZCode 会话** | 候选 → 验收三件套 → add_events → build → deploy |
| 本地定时采集（news_harvest.py） | 让位机制 | 检测到 `data/derived/n8n_active.json`（7 天内有心跳）即跳过采集，只消费 n8n 队列。**n8n 上线那天：`touch data/derived/n8n_active.json` 即完成交接** |
| 消费队列 | ZCode | `data/derived/n8n_queue/` 目录为约定入口；本会话见文件即按批次管线处理 |

## 六、纪律（长期不变）

1. n8n 永不直接产成品条目；成品入库必经「验收三件套 + add_events + build」。
2. 正文禁政治人物姓名（职务/机构泛称；企业家/科学家/运动员/艺术家可写名）。
3. 敏感词表只存在于服务端代码，绝不进任何 LLM prompt。
4. 编造 URL = 整批回滚；单源条目 date_confidence=single-source，两源才 verified。
5. 并行会话：定点 add、共享区最小窗口、开工跑 lane_check。
6. 记忆沉淀：每轮新坑写进 memory + PROGRESS，防重复踩。
