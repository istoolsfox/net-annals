## 一、现状基线（2026-10-26 实测，仓库口径）

| 指标 | 数值 |
|---|---|
| 骨架单位 | 34 省 / 367 市 / 3361 县 |
| 全库事件 | 6137 条 |
| 挂载到地域的事件 | 1493 条（24%） |
| 有事件的单位 | 290 个（省 3 / 市 265 / 县 22） |
| 零事件城市 | 102 个（含 13 个停用表城市，现行规则永不自动挂载） |
| 县级覆盖率 | **0.7%**（22/3361，仅白名单） |
| 单位事件数中位数 | **2 条**（头部：北京 335 / 上海 219 / 深圳 81 / 广州 60） |
| 挂载事件按年 | 2020 年全库 245 条仅 45 条挂载；1990 年 73 条仅 21 条 |

结构性瓶颈两个，缺一不可：
1. **匹配侧**：geo_match 只认 title+summary_30s 文本；县级仅 22 个白名单；13 个停用表城市（中山/朝阳/吉林等）永不自动挂载；事件无结构化 place 字段（region 只有 cn/world 两值）。
2. **内容侧**：库里几乎没有县级内容。实测放开县级全量匹配也只能新增 ~208 个单位 +276 条——匹配升级是必要条件，不是充分条件。

## 二、目标体量换算（先算账）

用户目标：县级 ≥12 件/年、城市级 ≥60 件/年，跨度 1972-2026（55 年）：

- 城市级：367 市 × 60 × 55 ≈ **121 万条**
- 县级：3361 县 × 12 × 55 ≈ **222 万条**
- 合计 ≈ **340 万条**，为现全库（6137）的 560 倍
- 即使只做一年（任选一年）：367×60 + 3361×12 ≈ 6.2 万条

史料现实约束：
- 2000 年前普通县带精确日期的公开记录基本不可得（县志多为叙事、少精确到日）；地级市 1980 年代记录也需方志深挖。
- 2015 年后县级源才逐步丰富：县政府工作报告实事清单（每年 1 月发布，天然含上年十件大事）、县融媒体、公告类（区划调整/通车/上市）。

**结论（分层北极星口径）**：总量目标保留为北极星，执行按「层级 × 年代」分层推进——优先近年、优先重点县、城市先铺总量再逐年加密。

## 三、三步执行计划

### P0 基建先行（约 1-2 个工作轮，不做则补量挂不上）

1. **place 字段**：事件 schema 增加可选 `place: ["c:320100", "k:320115"]`（c=市 k=县，写入时显式指定挂载点）；geo_match 优先读 place 直挂，文本匹配退居兜底。validate_events / add_events 对地域批次强制要求 place。
2. **geo_match v2**：
   - 县级白名单 22 → 全量 3361，仅做全称匹配（`short + 县/市/区/旗` 完整词形），配易撞词负面表（大城/新兴/南山/朝阳类词需审核）；
   - 停用表 13 城恢复：全称形态匹配（「中山市」「包头市」）即可安全恢复，short 单字匹配继续禁用；
   - 直辖市区行维持省名挂载惯例。
3. **geo_gap.py**：单位×年缺口矩阵导出（对齐 gap_config.py 惯例，落 data/derived/），作为 P1/P2 的队列真相源，n8n 工作流 B 可直接消费。
4. 现库白捡：全量全称匹配实测 +208 县级单位 +276 条挂载（上线前人工审一轮误伤）。

### P1 城市级铺厚度（367 市）

目标序列：每市 ≥30 条（里程碑骨架）→ ≥60 条 → 近 10 年每市每年 ≥12 条 → 全跨度 60 条/年（北极星）。

每市题材配方（骨架十件套）：行政区划沿革、高铁/机场通车、开发区获批、世遗与国家级名片、上市公司注册地、大学设立、标志性企业创立、重大灾害与重建、文体场馆、轨道交通首线。

数据源（按可得性）：
1. 市政府官网「大事记」/「市志」栏目（多数地级市有在线版，逐省建域名清单）
2. 省级方志网（省情网 / 数字方志）
3. 人民网 / 新华网地方频道
4. cninfo 注册地映射（公司 → 市，工具已有 query 基座）
5. 民政部区划调整公告（每年全量、精确到日，天然合规源）
6. 维基「XX市」词条大事记段

产能对照：367 市 × 60 = 2.2 万条 ≈ GAP_FINDER 单轮产能（578 条）× 38 轮；按每月 3-4 个大批次轮可持续推进，约一年铺完总量骨架。

### P2 县级破冰（0.7% → 全覆盖骨架 → 近年加密）

- 第一步：**每县 ≥1 条入册**（重点县优先：390+ 县级市 / 百强县 / 灾疫县 / 文旅名县）；
- 第二步：每县 ≥5 条（十年跨度）；
- 第三步：2015-2026 每县每年 ≥12 条（近年源最厚，是 12 件/年目标现实的落地段）；
- 北极星：全跨度 12 条/年 × 55 年 = 每县 660 条（总量 222 万），挂 ROADMAP 长期目标，执行按重点县逐个吃。

数据源：
1. **县政府工作报告**（每年 1 月，含上年实事清单——每县每年 10-12 条的天然骨架源，批处理友好）
2. 县融媒体公众号（源散、逐县建映射成本高，重点县先行）
3. 县级市 / 县 Wikipedia 词条
4. 上市公司注册地（百强县重仓，cninfo 映射复用）
5. 中国县域经济报等县域媒体（可访问性待实测）

### P3 源工程与产能

- n8n 工作流 B 扩展「地方政府大事记」子流：逐省维护 gov 域名清单，先 3 市最小闭环再放量。
- cninfo_announcements.py 增 `--by-region` 模式：先抓巨潮公司接口建 secCode→注册地映射，再按市/县出队列。
- 每批入库后重跑 geo_gap.py 刷新缺口队列；geo 挂载数与 build_geo 一并进 deploy 流程（已接入）。

## 四、决策点与建议

1. **口径**：建议采纳「分层北极星」——P1 先做每市 60 条总量（而非首年即 60/年），P2 县级近年段（2015+）先兑现 12 件/年。
2. **县级路线**：建议先「重点县深度」（每县 5-12 条）后「全量骨架」（每县 1 条）——重点县读者价值高且源厚。
3. **产能分配**：地域方向将占用主要产能，年段补条 / 日期补证等其他方向需降速或暂停（由用户裁定）。

## 五、纪律

- 红线沿用全库：政治人名禁写、编造 URL 整批回滚、milestone Agent 全 false、定点 add。
- 地域批次条目 title+summary 必须含市/县名（挂载依赖），place 字段显式声明。
- 与并行会话共用 data/geo_index.json（生成产物，可随时由 geo_match 重生成，不手改）；places.json 骨架改动需记 notes。
