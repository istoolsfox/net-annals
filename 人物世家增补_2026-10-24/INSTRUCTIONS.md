# 人物志 / 世家志 「中等详细度」增补任务说明

## 目标

为编年史的人物 / 世家写出**中等详细**的档案：比简略厚、比百科轻。读者标准——看完能大概懂"**这是谁 / 这是什么、经历了什么、现在怎样或怎样结束的**"。

## 输入

`subjects/` 下的批次文件：JSON 数组，每项是现有记录（已含 headline / summary_30s / timeline 等字段，可作为事实底稿）。你只负责分配给你的那批。

## 增补字段（输出为 JSON 对象，key = 记录 id，value 只含以下增量字段）

- **bio**：300 字左右（250~420）中等小传 / 兴衰概述。结构：一句话定位 → 出身 / 起点背景 → 主线过程（怎么起来的、关键转折）→ 现状或结局。客观简体中文，无感叹号，不堆形容词，不写"具有重要意义"式空话。
- **timeline**：10~18 条 `{date, acc, text}`，**时间升序**，覆盖完整弧线：起点（出生 / 创立 / 前身）→ 关键起步 → 上升与转折（成败都要写）→ 巅峰 / 代表作 → 结局。
  - 已故人物 / 已关停企业：写到终点与身后；
  - **在世人物（death 为空）/ 运营中企业：最后一条写最近现状，绝不编造死亡、重病、关停**。
  - `date`: "YYYY-MM-DD"；`acc`: "exact" | "month" | "year"，**不确定就降级**，月/年精度时日期位可填 01（如 2005-06-01 + acc:"month"）。
  - `text`: 40~120 字，写清事件 + 背景 / 意义，拒绝空洞评语。
- **legacy**：1~2 句。人：留下的东西 / 行业意义；在世者写现状（现任职务 / 近况）。企业的"现状与遗产"太薄就重写。
- **controversies**（可选）：知名争议 1~3 条，一句一条；没有就不给。
- **sources**：2~4 个可靠来源 URL（维基百科 / 官方站 / 权威媒体），用 WebSearch 核对过关键日期。

## 硬规则

1. **绝不虚构**：不确定的日期降 acc 或在 text 里用"约 / 前后"表述；查不到的事实不写。
2. **在世者严禁写死亡 / 病重；active 企业严禁写关停**。已故 / 已关停的，death / dissolved / status 查得准就修正后一并输出。
3. 原 timeline 里正确的条目可改写并入新 timeline；错误的修正。
4. 中文写作；通行中文译名；专有名词首现可附英文。国际历史人物（如达·芬奇）同样照常增补。
5. 输出 UTF-8 JSON，**无注释、不要 markdown 代码块包裹**。
6. 每条记录都必须处理，一条不落。

## 效率

知名对象靠你已有知识写，拿不准的日期 / 数字才 WebSearch 核对；每个对象至多 1~2 次搜索，控制总时长。
